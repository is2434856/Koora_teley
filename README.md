# Telegram Channel Relay

مشروع Python باستخدام Telethon يقوم بقراءة قناة Telegram عامة بواسطة **حسابك الشخصي**، ثم نشر الرسائل المسموح بها في قناة الهدف بواسطة **البوت**.

## ما الذي ينقله؟

- الصور التي تحتوي على وصف/تعليق (Caption).
- الرسائل النصية التي تحتوي على **8 كلمات أو أكثر**.
- يحافظ على تنسيق Telegram الموجود في النص مثل **العريض** والمائل والتسطير والاقتباس والكود وغيرها عندما يسمح Telegram بإعادة استخدامها.
- يحاول الحفاظ على الرد على رسالة سابقة عندما تكون الرسالة الأصلية التي يرد عليها قد تم نقلها سابقاً.
- النشر يتم بواسطة البوت، وليس بواسطة الحساب الشخصي.

## ما الذي يمنعه؟

يتم تجاهل الرسالة كاملة، وليس تنظيفها أو حذف الجزء الممنوع منها، عند وجود أي من الآتي:

- رابط ظاهر مثل `https://...` أو `www...` أو `t.me/...`.
- رابط مخفي داخل نص Telegram (Text URL / inline link).
- معرف Telegram مثل `@username`، بما في ذلك المنشن المخفي.
- أزرار أو Reply Markup.
- الاستفتاءات (Polls).
- الرسائل المحولة/Forwarded.
- الفيديوهات.
- أي وسائط غير الصور المسموح بها.
- رسائل الخدمات/الإجراءات.
- أنواع القوائم/المهام التي تظهر كوسائط ToDo/Checklist عندما يوفرها Telegram API.
- الرسائل التي تحتوي على أي كلمة/عبارة ممنوعة في الإعدادات.
- النصوص وحدها التي تقل عن 8 كلمات.
- الصور التي لا تحتوي على وصف.

### الكلمات الممنوعة

- فعالية
- التوقعات
- الفائز
- تابع
- شارك
- تفاعلا
- تفاعلآ
- الاعضاء
- مسابقة
- مسابقه
- الحسين
- حسين
- العباس
- كربلاء
- قناتنا
- قنواتنا
- قناة المصدر

## آلية الفحص

GitHub Actions يشغل المشروع كل ساعة (`00 * * * *`). كل تشغيل:

1. يجلب آخر **30 رسالة** من القناة المصدر.
2. لا يعالج إلا الرسائل التي تاريخها ضمن **آخر ساعة**.
3. يرتب الرسائل من الأقدم إلى الأحدث قبل النشر.
4. يمنع التكرار بواسطة `source_message_id` وبصمة محتوى (`fingerprint`).
5. يحفظ خرائط الرسائل المنقولة لاستخدامها عند الحاجة إلى الردود.
6. يكتب ملف الحالة `data/state.json` ثم يقوم الـ workflow بحفظه في المستودع.

> لا يوجد اعتماد على SQLite هنا، لأن ملف SQLite ثنائي قد يسبب تعارضات Git عند تشغيل GitHub Actions أكثر من مرة.

# 1. المتطلبات

ستحتاج إلى:

- حساب Telegram شخصي لديه إمكانية قراءة القناة المصدر.
- Bot من `@BotFather`.
- قناة هدف تملكها أو تديرها، ويكون البوت فيها **مشرفاً** مع صلاحية نشر الرسائل.
- حساب GitHub ومستودع للمشروع.
- Telegram API ID و API HASH.

Telethon 1.45.0 هي النسخة المثبتة في المشروع.

---

# 2. الحصول على API ID و API HASH

ادخل إلى:

`https://my.telegram.org`

ثم:

**API development tools → Create new application**

واحصل على:

- `API ID`
- `API HASH`

لا تضع API HASH داخل الكود أو في ملف منشور للعامة.

---

# 3. إنشاء البوت

من `@BotFather`:

1. استخدم `/newbot`.
2. أنشئ البوت.
3. احفظ **Bot Token**.

ثم أضف البوت إلى القناة الهدف كمشرف، مع صلاحية نشر الرسائل.

---

# 4. إنشاء Telegram Session لحسابك الشخصي

GitHub Actions لا يستطيع تنفيذ تسجيل دخول Telegram تفاعلي في كل تشغيل، لذلك نستخدم **String Session** ونضعها في GitHub Secret.

ثبّت Python وTelethon على جهازك، ثم شغّل:

```bash
pip install telethon==1.45.0
python generate_session.py
```

سيطلب منك:

- API ID
- API HASH
- رقم الهاتف
- كود Telegram
- كلمة مرور التحقق بخطوتين إذا كانت مفعلة

في النهاية يطبع `TELEGRAM_SESSION_STRING`.

**لا تشارك هذا النص مع أي شخص ولا تضعه في Git.** امتلاك Session String قد يسمح بتسجيل الدخول إلى جلسة الحساب.

### على Android / Pydroid

يمكن تنفيذ نفس الخطوات داخل Pydroid 3:

```bash
pip install telethon==1.45.0
python generate_session.py
```

---

# 5. إعداد GitHub Secrets

من المستودع:

**Settings → Secrets and variables → Actions → New repository secret**

أضف:

| الاسم | القيمة |
|---|---|
| `TELEGRAM_API_ID` | API ID الرقمي |
| `TELEGRAM_API_HASH` | API HASH |
| `TELEGRAM_SESSION_STRING` | الناتج من `generate_session.py` |
| `TELEGRAM_BOT_TOKEN` | توكن البوت من BotFather |
| `SOURCE_CHANNEL` | مثال: `@source_channel` |
| `TARGET_CHANNEL` | مثال: `@my_target_channel` |

يمكن استخدام معرف القناة الرقمي في الحقول الأخيرة أيضاً إذا كان ذلك مناسباً لحساب Telegram.

---

# 6. رفع المشروع إلى GitHub

ارفع الملفات كما هي إلى مستودع جديد.

بعد الرفع:

- تأكد أن `data/state.json` موجود.
- لا ترفع ملفات الجلسة `.session`.
- لا تضع أي Token أو API Hash داخل الملفات.

---

# 7. التشغيل التلقائي

الملف:

`.github/workflows/relay.yml`

يشغل المشروع تلقائياً كل ساعة، كما يحتوي على `workflow_dispatch` للتشغيل اليدوي.

للتجربة قبل انتظار الساعة، افتح:

**Actions → Telegram Channel Relay → Run workflow**

---

# 8. تشغيل محلي لاختبار المشروع

بعد ضبط متغيرات البيئة، يمكنك تشغيل:

```bash
python main.py
```

وللتجربة الفعلية استخدم الرسائل المسموح بها في القناة المصدر.

# ملاحظات مهمة حول الردود

إذا كانت رسالة المصدر ترد على رسالة سابقة:

- إذا كانت الرسالة الأصلية قد نُقلت بالفعل، سيحاول البوت جعل الرسالة الجديدة **رداً على النسخة المنقولة**.
- إذا كانت الرسالة الأصلية لم تُنقل بسبب أحد شروط الاستثناء، فلن يكون هناك رسالة هدف صالحة للرد عليها، ولذلك تُرسل الرسالة الجديدة بدون Reply بدلاً من اختلاق رد غير صحيح.

هذا مهم خصوصاً عندما تكون القناة المصدر تستخدم ردوداً أو سلاسل منشورات.

# ملاحظات مهمة حول إعلانات Telegram

المشروع يحتوي على فحوص دفاعية لأي نوع رسالة تُعرّفه مكتبة Telethon على أنه Sponsored/Ad، لكن رسائل Telegram المدفوعة/الممولة ليست دائماً ممثلة كمنشورات عادية في سجل القناة. لذلك لا يتم اعتبار كلمة مثل «إعلان» وحدها سبباً لتجاهل المنشور، حتى لا يتم حذف أخبار حقيقية تحتوي على هذه الكلمة.

# الأمان

الملفات الحساسة التي يجب أن تبقى في GitHub Secrets فقط:

- API HASH
- Session String
- Bot Token

لا تضعها في `config.py` ولا داخل Workflow مباشرة.
